## 0. 结论

1. **「老套」不是配色一个点的问题，而是三层叠加**：令牌层还停留在 iView 时代（`#2d8cf0` + 8px 圆角 + 12.5px 正文），骨架层虽有「232px 侧栏 + 56px 顶栏」，但顶栏只有面包屑和用户区、页面又在顶栏下重复一层页头，页面层则每页各写一套内联样式。只换主色不会变好看，必须按 **令牌 → 骨架 → 页面** 的顺序改。
2. **「难用」里有一半是视觉造成的**：列表用三种彩色徽标表达来源与类型、没有任何状态点或绑定信息、行内三个按钮同时常驻、删除走 `window.confirm()`，用户在扫读阶段就失去了判断依据。这部分与 UX 规格里的功能缺口（revision、单文件写、健康字段）叠加，需要一起做。
3. **先做 V-1 的一行热修，再谈视觉**：文件编辑门控写反了——`canEditFiles` 要求 `detail.source === 'nacos'`（`SkillsView.vue:80-82`），而本机已是 db 源、后端 `PUT /{id}/files` 也不按来源拦截（`SkillAdminController.java:207-229`）。结果是最痛的「改一个参考文件」在 UI 上不可达，却被排到 V4。V-1 只改一个判断，应先于所有视觉工作上线。
4. **建议分 5 批落地（V0–V4，约 9–11 人日，另加 V-1 热修 0.5 人日）**：V0 只改令牌和基础控件（低风险、可截图回归），V1 改外壳，V2 重做列表，V3 把抽屉升级为工作台，V4 做分栏编辑器与导入预检。跳过 V0/V1 直接重做单页，会得到「新页面套在旧外壳里」的割裂感。

### 1.3 归因

- **令牌层**：颜色、圆角、字阶是 2021 年前后 iView / Ant Design 2 的产物，和现在主流 SaaS 控制台差了一代；部分令牌（`--sidebar-active`）已经腐烂失效。
- **骨架层**：`AppLayout` 是「232px 侧栏 + 56px 顶栏」，但顶栏只有面包屑和用户区，页面标题、统计、筛选全压在内容区顶部，等于每页都自建一套页头。
- **页面层**：`SkillsView.vue` 1138 行单文件承载列表、抽屉、四个页签、三个弹窗，样式多为行内 `style`，无法复用也无法统一。

## 2. 业界基准：借鉴什么，不照搬什么

| 参考 | 借鉴 | 不照搬 |
| --- | --- | --- |
| **Linear** | 单 accent、灰阶分层、密集列表、hover 才出操作、⌘K 全局搜索、状态用点 | 键盘优先的极客交互（本项目用户是 HR/管理员） |
| **Vercel Geist** | 1px hairline 代替阴影、6px 圆角、纯黑白灰 + 一个强调色、字重 600 的标题 | 全 monochrome（需要保留绿/琥珀/红的语义状态） |
| **GitHub Primer** | 6px 圆角、状态点 + 文本、表格 40px 行高、danger 只在确认后出现 | 其表单密度（比管理台更紧） |
| **Stripe Dashboard** | 数据表 + 筛选 chips、指标行的「主次」处理、右侧详情抽屉 | 其品牌紫与插画风格 |
| **Shopify Polaris** | 资源索引页范式：标题 / 主操作 / 视图分段 / 筛选 / 列表 / 分页；空态三段式 | 其卡片化倾向（会把列表撑高） |
| **Postman / Notion** | 左侧文件树 + 右侧编辑器的分栏工作台；保存状态条 | 其自由排版（技能正文需要固定结构校验） |

> 一句话：**取 Linear 的克制、Geist 的线条、Primer 的状态语义、Polaris 的索引页结构。**

## 3. 设计原则

1. **内容优先**：chrome（页头、统计、工具条）总高度 ≤ 120px（量法：内容区顶边到第一条数据行顶边 ≤ 160px）；首屏至少 10 行数据。
2. **单一强调色**：蓝色只用于主操作、选中态、链接；绿/琥珀/红只表达状态，不做装饰。
3. **状态即语义**：状态用 6px 圆点 + 文本；标签默认中性灰，仅「已覆盖 / 只读」等需要告警时着色。
4. **密度可控**：13px 正文、40px 表格行、24px 页面内边距；不用 12.5px 承载正文。
5. **可预测**：列表 → 工作台 → 编辑器是同一条路径的逐级展开，交互模式（保存、返回、确认）三处一致。

| 语义 | 现值 | 新值 | 理由 |

| `--panel` 面板 | `#ffffff` | `#ffffff` | — |
| `--line` 分隔线 | `#e8eaec` | `#e6e8ee` | 更中性，去掉绿调 |
| `--line-2` 强分隔 | `#dcdee2` | `#d7dbe3` | 输入框 / 表头底边 |

| `--ink-2` 次文本 | `#515a6e` | `#4b5465` | — |
| `--ink-3` 辅助 | `#808695` | `#6b7484` | 现值对白底约 3.6:1，不达 AA；新值约 4.7:1 |

| 侧栏底 | 渐变 `#203042 → #1a2431` | `#101418` 纯色 | 中性近黑，和内容区脱开；选中态由蓝色渐变改为白字 + accent 竖条 |

> 命名对照：本文与原型用 `--ink / --line / --accent` 这类语义名方便阅读，落地时**沿用现有变量名**，避免 20 个文件同时改：`--ink→--text`、`--ink-2→--text-soft`、`--ink-3→--muted`、`--ink-4→--faint`、`--line→--border`、`--line-2→--border-strong`、`--accent→--primary`、`--panel→--surface`、`--green / --amber / --red→--success / --warning / --danger`。

> 原型里 muted 用 `#7e8798` 仅作演示；落地请用上表 `--ink-3`（即 `--muted: #6b7484`），否则 11–12px 辅助文字不达 4.5:1。

### 4.2 字阶

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 22 / 1.25 | 600 |
| 区块标题 / 工作台标题 | 17–21 / 1.3 | 600（ID 用等宽） |
| 正文、表格 | 13 / 1.6 | 400 |
| 表格表头、表单标签 | 12 / 1.5 | 500，颜色 `--ink-3` |
| 辅助信息、时间戳 | 11.5 / 1.5 | 400，颜色 `--ink-3` |
| 徽标、状态文本 | 12 / 1.4 | 500 |
| 代码、ID、路径 | 12 / 1.5，`tabular-nums` | 400，等宽栈 |

规则：**中文正文不设负字距**；负字距只用于 21–22px 的英文/等宽标题（原型已如此）。**字重只用 400 / 500 / 600**：`650` 只有可变字体支持，Segoe UI 与微软雅黑会回退到 700，中文标题会发黑。中文最小字号取 12px——11px 的中文状态文案在 125% 缩放下不可读。

### 4.3 间距、圆角、阴影、动效

| 项 | 值 |
| --- | --- |
| 间距序列 | 4 / 8 / 12 / 16 / 20 / 24 / 32（页面内边距 24，区块间距 16，表单项 12） |
| 圆角 | 容器 12 / 控件 8 / 徽标与输入 6 / 圆点 50% |
| 阴影 | 仅两级：`0 1px 2px rgba(16,24,40,.05)`（面板）；`0 12px 32px rgba(16,24,40,.12)`（浮层 / 抽屉） |
| 动效 | 120ms（hover） / 180ms（抽屉、弹窗）`cubic-bezier(.2,.8,.2,1)`；尊重 `prefers-reduced-motion` |

### 4.4 迁移策略

`styles.css` 是全局共享的：`router/index.js` 里 20 条页面路由（login、chat、14 个 admin 页、KB 3 屏、我的工作偏好）都会吃到改动。V0 不能「换值即上线」，按三条约束做：

1. **只做加法**：新增 `.tag / .dot / .btn-*` 与字阶变量；`.badge`、`.table-wrap`、`input` 的旧规则保持不动，各页迁移完再删。徽标去 pastel 只在技能页新组件里生效，不追溯改其它页面——否则一次提交会把审计、员工、批次页的语义色一起改掉。
2. **开关化**：新令牌写进 `body.theme-v2`，`:root` 保留旧值；V0/V1 通过 `<body class="theme-v2">` 灰度，出问题摘 class 即回退，不必 revert 提交。
3. **语义色分两步**：V0 只动中性色与字阶；`--primary / --danger / --success` 等语义值放到 V2，技能页验收通过后逐页切换。

变量名保持现状（`--primary`、`--border`…），本文的 `--ink`、`--accent` 只是语义别名。V0 的截图范围是**全部 20 条页面路由**，不是「12 个主要页面」。

## 5. 骨架改造

### 5.1 外壳形态（决策 D1）

现状已有「232px 文本侧栏 + 56px 顶栏 + 工作区切换（ws-switch）」，即 M8/D1 的「双工作台」在导航层已经落地。本节的取舍是**要不要把技能模块换成图标 rail**：

| 方案 | 结构 | 优点 | 代价 |
| --- | --- | --- | --- |
| **B 重绘现有外壳（推荐，V1）** | 保留 232px 文本侧栏与 ws-switch，仅去渐变、统一选中态、顶栏补环境标识 | 改动集中在样式，导航与权限零回归；技能仍能和其它模块互跳 | 内容区少 176px 宽，列表需要更克制的列 |
| A 内容工作台 | 56px 图标 rail（原型所用的形态）+ 52px 顶栏 | 数据区更宽，视觉更接近 Linear | 9 个一级菜单要靠图标记忆；与现有 ws-switch 冲突，需单独路由分支 |

推荐：**V1 走 B**；A 作为 P2 备选，等技能/知识库真的成为独立工作台、且菜单能收敛到 5 个以内再评估。原型里画 rail 是为了展示「内容优先」的极限形态，落地时不要求照搬宽度。

### 5.2 顶栏（现有 56px，重绘）

- 左：面包屑 `技能 / poetry-skills`（可点回列表；根级固定为工作区名，不再写死「协同智能体」）。
- 中：全局搜索框（P2，占位 `搜索技能、智能体… ⌘K`）。
- 右：环境标识（`db 源` / `Nacos`）+ 用户卡片。
- 保留 56px 高度（与现有外壳一致，避免所有页面重排）；改的是底色（`--panel`）、底边 hairline、去掉阴影，滚动时吸顶。

### 5.3 内容区

- padding 24；最大宽 1280；列表页不留卡片外壳（表格直接铺在 `--panel` 上，只有 1px 边）。
- 抽屉/弹窗层不再叠在表格上：工作台是**页面**（`/platform/skills/:id/:tab`），不是抽屉。这一条同时解决刷新丢失、无法分享链接的问题（UX 规格 F8）。

## 6. 页面级规格

> 下列 5 屏均在原型中可切换查看。线框按原型的 56px rail 绘制（§5.1 的方案 A）；若 V1 按推荐走方案 B，内容区整体右移即可，页面内部结构不变。
>
> **评审时请注意**：原型只演示方案 A，落地按 §5.1 的方案 B（保留 232px 文本侧栏）。不要据原型认为本次要换掉导航。

- **页头**：标题 22 + 一行副标题（13px `--ink-3`）+ 右侧一个 primary、一个 ghost。只允许一个 primary。
- **统计条**：从 6 个等权数字降为 4 个（技能数 / 被绑定 / 正文总量 / 缓存命中），放在视图分段右侧或作为副标题补语；目录构建耗时与缓存命中不删除，收进列表页脚一行 11.5px 小字——运维排障要用，P2 再进「运行状态」弹层。
- **视图分段（segmented）**：带计数，点击即筛选；当前视图用白底 + 1px 边 + 阴影，其余透明。
- **筛选**：搜索 280px；来源下拉必须包含 `db`（当前缺失，`SkillsView.vue:547-551`）；已选条件以 chip 展示，可单个移除。
- **表格列**：技能（ID 等宽 13 + 说明 12 换行截断 1 行）/ 来源（中性 tag）/ 状态（点 + 文本，只读用琥珀、不可用用灰）/ 绑定（头像叠 3 + `+n`，无绑定显示 `—`）/ 文件数 / 更新时间（相对时间，hover 显示绝对时间）/ 操作。
- **行内操作**：常驻一个 32px 的「⋯」（hover 才出现的操作在触屏与键盘下不可达），菜单含「打开 / 编辑 / 删除」；删除走 §7 的确认框。工作台危险区是**第二个**入口，不是唯一入口——否则 V2 上线到 V3 之间没有删除能力。

### 6.2 工作台（详情）

```
平台 / 技能 / poetry-skills                        ● 已启用   [编辑] [⋯]
poetry-skills                                                    v7
诗词创作技能包 · db 源 · 更新于 2 小时前 · 3 个智能体在用
┌ 正文 │ 参考文件 4 │ 脚本 3 │ 数据 │ 版本 7 ────────────┐ ┌ 检查栏 ──┐
│                                                      │ │ 质量检查   │
│  ## 角色                                              │ │ ✓ 有标题   │
│  ...                                                 │ │ ✓ 规则段落 │
│                                                      │ │ 字数 4,210 │
│                                                      │ │ 绑定 3     │
└──────────────────────────────────────────────────────┘ └───────────┘
```

- **头部**：面包屑、ID（等宽 21）、状态点、主操作「编辑正文」、`⋯`（导入新版本 / 删除）。
- **副标题**：说明、来源、更新时间、使用方，全部 12px，用 `·` 分隔。
- **内容**：占 2/3；右侧检查栏 1/3、sticky。
- **页签**：正文 / 参考文件 / 脚本 / 数据 / **版本**（新增）。版本页签**只对 db 源显示**：`versions` 对 Nacos 返回空列表、`rollback` 默认抛「没有版本历史」（`SkillStore.java:146-159`）；Nacos 技能不出现该页签，也不出现回滚按钮。
- **版本语义（必须写进 UI）**：回滚 = 追加一条新版本行并把指针移过去，**正文与参考文件清单一起**回到目标版本（`JdbcSkillStore.rollback:787-838` 的 `copyResources`），**不**回滚说明与执行开关（`metaOf` 取当前值）。确认框要写明「将替换：正文 + N 个参考文件；不会改动：说明、执行开关」。
- **版本不含文件单改**：`replaceFiles` 不追加版本行（`JdbcSkillStore.java:846-849`，「版本只跟正文走」），所以「v7」不是文件包的可回滚快照，UI 不要暗示它包含文件历史。
- **正文渲染**：当前是 `<pre>`（`SkillsView.vue:676`）。P1 先保留等宽但限制行宽 76ch、行高 1.65；P2 引入 markdown 渲染（需新增依赖，单列决策）。
- **数据页签**：状态卡（READY / INITIALIZING / FAILED + 时间）+ setup 命令 + 数据大小 + 操作按钮；日志默认折叠，只显示尾部 20 行并标注「初始化容器日志」。
- **危险区**：删除技能需要输入技能 ID 确认；被智能体绑定时直接禁用并列出名称（后端已返回，`SkillAdminController` delete 分支）。

### 6.3 编辑器（分栏）

```
← 返回    poetry-skills · v7 · 有未保存修改              [取消] [保存]
┌ 说明 / 元信息 ────────────────┐ ┌ 质量检查（实时） ───────────┐
│ 说明  [诗词创作技能包      ]  │ │ ✓ 标题                         │
│ 执行   ○ 关闭 ● 开启          │ │ ✓ 含「规则/步骤/流程」         │
│ 正文  ┌────────────────────┐ │ │ ✕ 正文字数 180 < 200           │
│       │ ## 角色            │ │ │ 字符 4,210 / 200,000           │
│       │ ...                │ │ ├ 保存 ────────────────────────┤
│       └────────────────────┘ │ │ 变更说明 [______________]      │
└──────────────────────────────┘ │ ● 基于 v7 保存（他人改动会 409）│
                                 └────────────────────────────────┘
```

- 保存条固定底部：dirty 状态、`⌘/Ctrl+S`、变更说明输入（200 字）、revision 提示。
- **409 冲突**（原型有「演示冲突状态」开关；只对 db 源——Nacos 是整包发布、没有 revision，永远不会 409，保存条不能笼统承诺「他人改动会 409」）：顶部琥珀条「他人已保存为 v8」，只提供两个出口——**重新加载**（丢弃我的修改）与**另存为新版本**（把我的正文下载为 .md，人工合并后再保存）。
  - **不做「覆盖保存」**：后端把空 revision 当「不检查」，这个按钮等于把绕过乐观锁做成产品功能，正是要防的静默覆盖。
  - **不做「查看差异」**：`GET /{id}/versions` 只返回 `{id,total,versions}`，版本行不含正文（`SkillAdminController.java:169-178`），前端没有 diff 数据源。留作 P2，前置是新增 `GET /{id}/versions/{n}/body`。
- 质量检查实时跑 `SkillContentRules` 同款规则（前端复刻文案），错误阻塞保存，警告不阻塞。
- 编辑器不再用 860px 弹窗（`SkillsView.vue:802,819`），改为整页或全屏抽屉。

### 6.4 新建（两路，模板列 P2）

两张等宽卡片：**从空白创建** / **从技能包导入**。卡片 42px 图标 + 标题 15 + 一句说明 + `→`；hover 抬 1px；选中态 accent 边。

第三张「从模板创建」列为 P2：仓库里的 `nacos-skills/` 只是文件目录，没有列模板的后端接口，先不要画一个点不动的入口。

理由：当前只有一个「新增技能」弹窗，导入藏在页头按钮里，用户不知道还有第二条路。

### 6.5 导入预检

左侧 240px 文件树（目录可折叠、显示文件数与大小），右侧上方「新增 3 / 覆盖 2 / 其余 4」的文件列表，下方摘要卡（ID、说明、setup、数据上限）与预检结果（三项通过 + 一项提示）。存在同名技能时给出琥珀警示条，说明会生成 v8 并允许先记下版本号回滚。

数据来源：`POST /import/zip?dryRun=true` **已经存在**（`SkillAdminController.java:330-360`，「不落库」），预览返回 `ImportResult(id, description, metadata, files[path,size,kind], setupCommand, dataMaxBytes, warnings, existing, dryRun)`（`SkillImportService.java:60-71`）。因此「新增 / 覆盖」可由路径集合与当前文件列表比对得出；但文件摘要没有内容 hash，「不变」判不出来——文案写「其余 N 个（未比对内容）」，或让后端在 dryRun 结果里补 per-file hash（属后端改动，必须写进依赖，不能算在纯前端批次里）。
