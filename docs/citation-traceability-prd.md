## 1. 结论先行

当前系统已经保存了“引用来自哪个知识库、哪个文档、哪一页”的结构化数据，但这些信息只藏在回答底部一个不显眼的「引用（N）」入口里；正文没有来源标记，原文不可点击，导出会丢来源，文档被删除或被重新解析后也无法解释当时的命中内容。用户看到“Kafka 部署步骤”这类回答时，无法判断它出自哪个库、哪个文件，也就无法信任。

本 PRD 的目标是把引用从“后台有数据”升级为“用户可感知、可点击、可复现、可审计的来源证据”。P0 聚焦“回答里直接看得到来源 + 来源快照不丢 + 导出带来源 + 失效可解释”，P1 做“点开原文并定位到分块”，P2 做“引用质量巡检与句子级依据校验”。

## 2. 背景与问题

### 2.1 用户反馈

> 没有体现引用的文件出自哪里，我需要的是比如 kafka 的相关知识来自哪个知识库哪个文件，可以进行追溯。给我一个 PRD。

本机实测中，一个 Kafka 部署类问题返回了 Elasticsearch 相关文档的引用：引用面板里确实能看到库名和文档名，但回答正文没有任何 `[n]` 标记，用户必须先发现并点开「引用（N）」才能看到来源，且无法点开原文核对。这类体验会被直接理解为“答案在编”。

### 2.3 产品缺口归纳

1. **不可见**：来源入口藏在 chip 里，正文没有 `[n]`，用户第一眼看不到“出自哪里”。
2. **不可达**：有 chunkId 却没有原文查看页，无法核对片段上下文。
3. **不可复现**：引用快照缺少查询词、检索时间、文档版本；文档重解析/删除后，历史引用无法解释当时命中了什么。
4. **不可带走**：导出的 Markdown 没有来源，会议纪要、工单无法附证据。
5. **不可信**：相关度不足或主题不符时没有“未收录/低置信”提示，模型容易把不相关文档写成答案。
6. **失效未处理**：文档删除、禁用、权限收回后，历史引用没有降级展示策略。

## 3. 目标与非目标

### 3.1 目标

- 用户在回答正文和回答下方都能直接看到：**哪个知识库 → 哪个文档 → 哪一页/哪一章 → 哪一段（分块）**。
- 任意一条引用都能回溯到回答时的检索上下文（查询词、时间、评分、召回通道）和内容快照。
- 引用可点击查看原文（P1），可复制、可导出、可审计。
- 来源失效、权限变化、文档更新时，引用有明确、诚实的降级状态。
- 证据不足时明确说“知识库未收录/依据不足”，而不是用不相关文档凑答案。

### 3.2 非目标

- 不做知识图谱、实体消歧或跨库文档合并。
- 不自动改写历史回答内容（避免历史答案漂移）。
- 不做引用计费、版权管理。
- P0 不引入重排模型；重排作为 P1/P2 的可选优化。
- 不把整篇文档塞进消息存储；只保存命中分块快照。

## 4. 用户与场景

| 角色 | 场景 | 期望 |
| --- | --- | --- |
| 普通员工 | 问“Kafka 部署步骤”“年假怎么算” | 回答里直接看到来源库和文件名，能点开核对 |
| HR/财务专员 | 根据制度回答员工质疑 | 能复制“库 › 文件 › 页码 › 原文片段”作为依据 |
| 知识库管理员 | 排查“为什么答错” | 能看到当时命中的库、文档、分块、评分、查询词 |
| 审计/合规 | 事后追溯某条回答的依据 | 即使文档已更新，也能看到回答时的内容快照与版本 |

### 4.1 用户故事

1. 作为员工，我问一个制度问题后，能在回答中看到 `[1]` 并点击它定位到“薪酬制度库 › 差旅报销管理办法.pdf › 第 4 页”，从而相信答案不是编的。
2. 作为 HR，我能一键复制引用文本，粘贴到邮件或工单中，包含库名、文件名、页码和原文片段。
3. 作为管理员，我能在历史会话中看到“该来源文档已被删除/重新解析”，并查看回答时的分块快照。
4. 作为审计人员，我能导出带完整来源清单的 Markdown，离线复核。

## 5. 现状数据流

```text
用户问题
  └─ PayrollChatService 路由到 KB 能力链路
       └─ KbQueryTools.kb_search(query, series_ids?)
            └─ KbSkillService 多库独立召回（VECTOR/BM25/TITLE_PATH）
                 └─ RRF 融合、按文档限流、topK 截断
                      └─ 返回 results[].series_id/series_name/hits[]
                           ├─ 工具结果回给模型（point_id K1..Kn）
                           └─ KbCitationCollector 采集（去重、重编号、240 字片段）
                                ├─ SSE citation 事件 → 前端流式引用面板
                                └─ assistant 消息 citations_json 落库
```

缺口位于最后两段：前端只在 chip 中展示；正文不渲染 `[n]`；引用快照信息不足；没有原文跳转。

## 7. P0 详细需求

### T1 回答下方固定来源区 + 内联角标

**问题**：引用只在「引用（N）」chip 里，正文没有来源标记。

**要求**：

1. assistant 消息只要 `citations.length > 0`，正文下方固定渲染「参考来源（N）」，不再依赖用户点 chip；默认展开前 3 条，其余折叠。
2. 正文渲染 Markdown 后，把裸角标 `[1]`–`[8]` 转成可点击上标/徽标：
   - 只匹配“独立数字角标”，不能破坏 Markdown 链接 `[文本](url)`、代码块、行内代码。
   - `n` 超出引用范围时不报错，保留原文并记录一次前端告警（便于发现问题）。
   - 点击 `[n]` 滚动到对应来源卡并短暂高亮；来源卡点击 `[n]` 可反向滚动到正文首次引用处。
3. 模型未输出任何角标时（本机小模型常见），仍然展示完整来源区，并在来源区顶部显示“以下为本次回答检索到的依据”；不伪造正文角标。
4. 流式输出过程中，已到达的 citation 事件即时进入来源区；最终消息与流式状态一致。
5. 旧的「引用（N）」chip 保留，但仅作为“打开来源详情”的快捷入口，与来源区指向同一数据。

**验收**：

- 回答含 5 条引用且正文有 `[1][3]`：来源区显示 5 条，点击 `[1]` 定位第 1 条。
- 回答含 5 条引用但正文无角标：来源区仍完整显示，页面无报错。
- 正文出现 `[9]`：不生成死链，控制台告警一次。

### T2 来源卡信息完整

每条来源卡（来源区与详情抽屉共用组件）至少展示：

| 信息 | 示例 | 数据来源 |
| --- | --- | --- |
| 序号 | `[1]` | `Citation.index` |
| 知识库 | 薪酬制度库 | `series_name` |
| 文档 | 差旅报销管理办法.pdf | `document_name` |
| 页码 | 第 4 页 | `page_no` |
| 章节路径 | 三、报销标准 | `title_path` |
| 分块序号 | 分块 #37 | 新增 `chunk_seq` |
| 召回通道 | BM25 / VECTOR | `routes` |
| 相关度 | 0.812 | `score` |
| 检索时间 | 2026-11-15 10:24:03 | 新增 `retrieved_at` |
| 查询词 | 出差住宿标准 | 新增 `query` |
| 片段 | 员工出差住宿标准…… | `snippet` |

**要求**：

- 库名与文档名必须同时可见，不能只显示 `知识库` 占位；缺失时显示“未知知识库/未知文档”并标记数据异常。
- 长文档名截断并提供完整 title 提示。
- 评分展示统一保留 3 位小数；页面说明“评分为多路召回融合分，仅用于排序，不等同于置信度”。
- 若同一文档命中多个分块，按引用序号分别展示，并标注各自页码/章节。

### T3 引用快照不可变

**问题**：当前只保存 240 字片段，且没有查询词、检索时间、文档版本；文档重解析后无法解释当时命中内容。

**要求**：

1. `Citation` 增加字段（见 §9.1）：`query`、`retrieved_at`、`chunk_seq`、`document_version`、`content_snapshot`、`low_confidence`。
2. 快照在回答生成时写入 `citations_json`，之后**只读**；文档更新、重新解析、删除都不得修改历史快照。
3. 旧数据兼容：历史引用缺少新字段时正常渲染，缺失行不显示，不抛异常。
4. `content_snapshot` 保存命中分块全文（截断上限见 D5），用于详情抽屉与导出；`snippet` 继续保留 240 字用于列表。
5. 单条 assistant 消息的引用快照总量设置上限（建议 64KB），超出按引用顺序截断并标记 `truncated`。

### T4 Markdown 导出包含来源

`exportMarkdown()` 在每条 assistant 消息正文后追加：

```markdown
### 参考来源
1. 薪酬制度库 › 差旅报销管理办法.pdf · 第 4 页 · 三、报销标准 · 分块 #37 · BM25/VECTOR 0.812
   > 员工出差住宿标准……
2. …
```

**要求**：

- 无引用时不输出该段。
- 片段取 `snippet`；如已有 `content_snapshot`，详情导出可选完整片段（见 D6）。
- P1 起在每条来源后追加原文链接（基于当前站点 origin + 深链参数）。
- 导出内容与页面展示使用同一份 `citations` 数据，避免两套逻辑。

### T5 来源失效与权限降级

**场景**：

- 文档被删除 / 被禁用 / 被重新解析导致 chunk 变化。
- 用户失去该知识库读权限。
- 知识库被停用。

**要求**：

1. 展示历史引用时不覆盖快照；实时校验失败时给出明确状态：
   - 文档不存在：“来源文档已删除，以下为回答时的内容快照”。
   - 文档已更新/重新解析：“来源文档已更新，快照可能与当前版本不同”。
   - 无读权限：“无权查看原文”，默认隐藏片段正文，仅保留库名/文档名/时间等元数据（D3）。
2. 校验失败不得导致消息接口 500；单条来源失败不影响其他来源。
3. 来源状态校验按需触发（打开详情/跳转原文时），列表渲染不逐条打接口，避免 N+1。
4. P0 至少实现“接口失败/403/404 的前端降级文案”，后端实时状态查询可放 P1。

### T6 未收录与低置信提示

**问题**：检索没命中或命中不相关文档时，模型仍可能给出看似确定的答案。

**要求**：

1. 检索返回 `BELOW_THRESHOLD` 或 `NO_READY_DOCUMENT` 时，回答必须明确“知识库未收录该内容”，不得展示来源卡，不得编造步骤（提示词已有约束，需在 UI 上同步体现）。
2. P0 增加最小相关性护栏：对“查询词 vs 来源文本（文档名 + 章节路径 + 片段）”做关键词重叠检查（中文二元组 + 英文/数字 token）；全部来源都无重叠时给引用集打 `low_confidence=true`，来源区显示“未找到与问题直接相关的依据，请谨慎参考”。
3. 低置信提示只做提醒，不改写答案（避免误伤）；阈值可配置并默认关闭灰度开关，验证后再开。
4. 不允许把“低置信”静默处理；至少在一次回答中可见。

### T7 多库分组

- 来源区按知识库分组，组头显示库名与条数；不同库的同名文档不得合并。
- 同一库内按引用序号排序。
- 组头可折叠，折叠状态只影响展示，不影响导出。

## 8. P1 详细需求

### T8 深链打开原文并高亮分块

- 新增可分享链接：`/kb?series={seriesId}&doc={documentId}&chunk={chunkId}`。
- 打开后自动：加载库详情 → 加载文档列表并选中目标文档 → 打开分块视图 → 加载目标分块及前后各 2 个分块 → 滚动并高亮。
- 提供“下载原件”入口（复用现有下载接口）。
- 无权限/文档不存在时：提示原因并停留在知识库列表，不白屏。
- 若聊天用户没有知识库管理页权限，需要新增只读来源查看入口（见 D2），不能直接复用 `@RequirePermission(KB_READ)` 页面。

### T9 引用详情面板与复制

- 详情抽屉补充 T2 全部字段与完整快照。
- 「复制引用」输出纯文本：`库名 › 文档名 · 第 x 页 · 章节 · 分块 #n · 片段`。
- 「复制链接」复制深链；无深链时按钮隐藏。
- 「查看原文」「下载原件」按钮按权限显示。

### T10 流式一致性

- 流式过程中同一 chunkId 不重复出现；最终消息用服务端重编号结果覆盖本地临时编号。
- 续流/刷新后，来源区与历史消息一致（读 `citations_json`）。

### T11 相关度护栏增强

- 将“关键词重叠”升级为可配置规则：
  - 查询实体词必须至少命中一个来源的标题/章节/片段；
  - 单库最低命中数；
  - 可选轻量重排（按标题路径权重、文档主题标签）后再截断。
- 命中不足时优先返回“未收录”，而不是硬凑 topK。

### T12 引用断链巡检

- 管理端可查看某会话/时间段的引用健康度：失效文档数、被重解析分块数、无权限来源数。
- 提供“重新检索最新版本”动作，生成新回答而不是修改旧回答。

## 9. 数据模型与接口

### 9.1 Citation 字段扩展

在 `payroll-common/.../domain/Citation.java` 现有字段基础上新增（snake_case 由全局序列化策略输出）：

| 字段 | 类型 | 必填 | 说明 | 旧数据兼容 |
| --- | --- | --- | --- | --- |
| `query` | String | 否 | 触发该引用的 `kb_search` 查询词 | 缺失→`""` |
| `retrieved_at` | String | 否 | 检索完成时间，ISO-8601 | 缺失→`""` |
| `chunk_seq` | Integer | 否 | 文档内分块序号 | 缺失→null |
| `document_version` | Long | 否 | 命中文档的 `config_version_id` | 缺失→null |
| `content_snapshot` | String | 否 | 命中分块全文快照（截断上限见 D5） | 缺失→`""` |
| `low_confidence` | boolean | 否 | 关键词重叠护栏结果 | 缺失→false |

实现要点：

- `KbQueryTools` 采集时把当前 `query` 与检索时间传给 `KbCitationCollector`（当前 `collector.record(outcome.result())` 未携带查询上下文，见 `KbQueryTools.java:275-288`）。
- 多轮/多次 `kb_search` 合并时，每条引用保留“产生它的那次查询词”，不要用最后一次覆盖。
- `point_id` 是单次检索内的编号，可能在不同调用间重复；跨调用以采集后的 `index` 为准，PRD 要求前端只使用 `index`。
- Jackson 反序列化旧 JSON 缺少新字段时按 null 处理，compact constructor 统一归一化。

### 9.2 消息接口

- 现有 `GET /api/chat/sessions/{id}/messages` 继续返回完整 `citations`（含新增字段），无需新接口。
- 若后续出现消息体过大，可将 `content_snapshot` 放独立表/对象存储，接口按需返回；P0 不拆。

### 9.3 知识库接口（P1）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/kb/series/{seriesId}/documents/{documentId}` | 文档元数据（已存在） |
| GET | `/api/kb/series/{seriesId}/documents/{documentId}/chunks?page=&size=` | 分块分页（已存在） |
| GET | `/api/kb/series/{seriesId}/documents/{documentId}/chunks/{chunkId}?context=2` | 新增：目标分块 + 前后上下文，供深链高亮 |
| GET | `/api/kb/series/{seriesId}/documents/{documentId}/download` | 原件下载（已存在） |

新增接口必须复用 `permissionService.requireRead(seriesId, user)` 的服务级校验，不依赖页面菜单权限。

### 9.4 存储

- `chat_messages.citations_json` 已是 LONGTEXT/CLOB，新增字段不需要 DDL。
- P0 不新增表；若启用“引用点击/反馈”再评估独立表（P2）。
- 单条消息快照上限 64KB，超出按序号截断并置 `truncated=true`。

## 11. 验收标准

### P0 必须通过

1. 任意一条带引用的 assistant 消息，回答下方固定出现「参考来源（N）」，每条同时显示库名、文档名、页码/章节、片段。
2. 正文含 `[n]` 时可点击并定位到对应来源；正文不含角标时来源区仍完整。
3. 刷新页面、断线续流、切换会话后，来源与首次回答一致（来自 `citations_json`）。
4. 导出 Markdown 包含每条回答的「参考来源」，字段与页面一致。
5. 检索无命中/低于阈值时，回答明确“未收录”，不出现来源卡，不输出编造步骤。
6. 来源文档被删除、重解析或权限收回时，页面有明确降级文案，消息接口不报 500。
7. 多库命中时按库分组，库名与文档名不合并、不丢失。
8. 旧会话（无新增字段）正常显示，无前端报错。
9. 新增字段按 snake_case 输出，前端读取 `series_name`、`document_name`、`chunk_seq` 等。

### P1 必须通过

1. 点击来源卡「查看原文」可打开 `/kb?series=&doc=&chunk=`，定位并高亮目标分块。
2. 无权限用户点击原文得到明确提示，不泄露片段与文档内容。
3. 「复制引用」「复制链接」可用，内容包含库名、文档名、页码、分块、片段。
4. 流式期间与最终消息的引用数量、序号、顺序一致。

## 12. 边界与异常

| 场景 | 期望行为 |
| --- | --- |
| 本轮无引用 | 不显示来源区；若为 KB 问题且检索为空，提示未收录 |
| 正文 `[n]` 越界 | 保留文本，不生成死链，记录告警 |
| 引用超过 8 条 | 按现有上限展示前 8 条，来源区注明“仅展示前 8 条” |
| 同一文档多分块 | 分别展示，不合并片段 |
| 跨库相同 chunkId | 去重键改为 `(series_id, chunk_id)`，避免误合并 |
| 文档重解析后 chunkId 变化 | 快照仍可读，标注“文档已更新” |
| 用户权限被收回 | 默认不展示片段，仅展示元数据与失效原因（D3） |
| 快照超出容量 | 按序号截断并标记 `truncated` |
| 模型返回伪引用编号 | 前端不渲染无效角标，来源区以服务端 citations 为准 |

## 13. 非功能要求

- **性能**：P0 不增加检索次数；文档元数据按需批量查询，避免逐条 N+1；单条消息最多 8 条引用，前端渲染开销可忽略。
- **安全**：引用片段属于知识库内容，展示/导出前必须确认当前用户对该库有读权限；提示词继续把文档内容视为不可信数据，防止注入。
- **审计**：P0 不改审计表；P2 可记录引用打开、下载、反馈事件。
- **兼容性**：新增字段全部可空；旧 `citations_json`、旧消息、旧接口调用保持可用。
- **可配置**：护栏开关与阈值走配置（如 `payroll.kb.trace.*`），默认保守，验证后开启。

## 15. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 本地小模型不遵守 `[n]` 规范 | 正文仍无来源标记 | 前端保底来源区，不依赖模型；不自动改写正文 |
| 片段快照增大消息体积 | 存储/传输变慢 | 240 字 snippet + 2KB content 上限，单消息 64KB 上限 |
| 聊天用户无知识库页面权限 | 深链 403 | D2 决定是否新增只读来源查看入口 |
| 权限收回后片段泄露 | 合规风险 | 展示前校验，默认隐藏片段（D3） |
| 相关性护栏误伤 | 正常回答被标低置信 | 默认灰度/可配置；只提示不改写 |
| 历史数据无新字段 | 展示异常 | 全部字段可空，缺失行隐藏 |

## 16. 决策点（评审时确认）

| 编号 | 决策 | 选项 | 建议 |
| --- | --- | --- | --- |
| D1 | 正文没有 `[n]` 时怎么办 | A. 仅强化提示词；B. 前端固定来源区保底；C. 后端改写正文补角标 | **B**。不改写模型正文，风险最低 |
| D2 | 原文查看入口权限 | A. 复用 `/kb` 与 `KB_READ`；B. 新增只读来源查看页/接口，按库读权限校验；C. P1 不做跳转，只看快照 | **B**，若确认所有聊天用户都有 `KB_READ` 则可用 A |
| D3 | 权限收回后的历史引用 | A. 全部隐藏；B. 保留元数据、隐藏片段；C. 全量保留 | **B** |
| D4 | 文档删除/更新后的引用 | A. 删除引用；B. 显示失效提示 + 回答时快照；C. 自动用最新版本重答 | **B**；C 会导致历史回答漂移 |
| D5 | 快照容量 | A. 仅 240 字片段；B. 240 字 snippet + 2000 字 content；C. 全文 | **B** |
| D6 | 导出是否包含完整快照与链接 | A. 仅片段；B. 片段 + 链接；C. 片段 + 完整快照 + 链接 | **C**（P1 起） |
| D7 | 相关性护栏上线方式 | A. 默认开启；B. 配置开关灰度；C. 仅记录不提示 | **B**，先观察误伤率 |
